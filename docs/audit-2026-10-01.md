# MCP audit: manuscript research, October 1, 2026

This audit exercised the actual stdio MCP server, not just the CLI. The research
trail covered multispectral imaging of the Archimedes Palimpsest, virtual
unwrapping of Herculaneum scrolls, and digitization of Codex Sinaiticus. Searches
led to article reads, extracted links, navigation to linked pages, PDF summaries,
page extraction, text queries, and chunked reads. TinyFish independently found
sources and retrieved two articles for comparison.

Four runs made **106 MCP tool calls**: 19 before changes, 29 after the initial
fixes, 29 with ten keyless providers enabled, and 29 on the final binary using
the reusable audit runner. These are point-in-time checks;
external providers and pages can change. This is a broad audit, not a guarantee
that every defect has been found.

## Findings and changes

| Finding | Resulting behavior and regression coverage |
| --- | --- |
| `web_read` ignored pagination in query and link modes | Every mode applies the same rune-based pagination and continuation marker; negative options are validated before fetching links. |
| `context: 0` silently selected two context lines | MCP distinguishes omission from explicit zero; callers can request only matching lines. |
| Query match caps hid omitted matches | Query output explicitly marks truncated matches. |
| Adding a huge length to a nonzero offset could overflow | Pagination compares the requested length with the remaining document length before addition. Unit and fuzz coverage include integer extremes. |
| Relative links used the original URL after redirects; short-page rendering left relative links unresolved | HTML conversion and link extraction resolve URLs against the final response URL and HTML `base`, including short pages. |
| MIME checks were case-sensitive and missing MIME headers returned raw HTML | Media types are parsed, normalized, and sniffed when absent; ordinary HTML renders consistently. |
| PDF downloads with opaque URLs and binary MIME types were rejected | PDF magic is recognized before binary rejection. PDF fetches check the signature rather than trusting a `.pdf` suffix. |
| Generic readers could return and cache HTTP 200 challenge pages | Recognized challenge titles/forms return explicit errors. Articles discussing challenges are still readable. |
| `web_read` on an arXiv PDF URL returned only the abstract | PDF URLs use full document extraction. Abstracts use the HTTPS Atom API, with public-page fallback if the API fails. |
| Two-column PDF prose interleaved left and right paragraphs | A conservative repeated-gutter heuristic reads prose columns in order, preserving spanning headings and ordinary short-cell table rows. The live Archimedes paper verified the improvement. |
| PDF content extraction could panic after successful header parsing | Both full and selected-page extraction recover parser panics into errors. A generated malformed content-stream fixture exercises this path. |
| PDF searches with no matches returned an empty success; image-only PDFs were also blank | Explicit no-match and possible-OCR messages distinguish these cases. Result truncation is visible; page-only reads extract at most the requested result limit. Page allocations are bounded at 10,000. |
| Oversized responses were silently truncated and cached as complete documents | Generic reads, link extraction, and PDF fetching reject responses over 10 MiB. Tests cover plain text, HTML, and PDF responses. |
| Each read left its newly allocated HTTP transport's idle connections open | Public read operations close their idle connections when finished. |
| Cached search responses shared mutable result/degradation slices | Stored and returned slices are copied; callers cannot alter another request's cached results. |
| Search cache keys ignored headers and used ambiguous field delimiters | Stable JSON keys include headers and preserve field boundaries; tests cover map order and delimiter collisions. |
| Canceled callers could receive cached data or poison provider health | Already canceled operations return context errors. Explicit caller cancellation preserves breaker health and releases a canceled half-open trial slot. Provider timeouts still count as failures. |
| Older in-flight searches could close a newly opened breaker | Generation tracking isolates calls admitted before a state transition. A deterministic concurrent regression checks a delayed success. |
| Loading persisted pages bypassed the in-memory entry cap | Disk loads enforce the same 256-entry cap as network loads; a 32 MiB rendered-content budget also bounds large cached pages. |
| Multiple processes used the same temporary cache filename | Writes use unique private temporary files followed by rename. |
| Disk-cache pruning could delete unrelated JSON in the selected directory | Pruning only considers the cache's 64-hex-character filenames. A regression preserves unrelated expired JSON. |

## Live provider observations

The expanded run configured DuckDuckGo, Yahoo, Bing, Google, Marginalia, Mojeek,
Wikipedia, Hacker News, Stack Exchange, and Crossref. All three initial searches
returned five results despite partial failures.

- DuckDuckGo returned useful general results. Wikipedia and the specialist APIs
  returned successful responses, although specialist sources are not necessarily
  relevant to every general query.
- Yahoo intermittently returned `unexpected EOF`. It recovered in the default
  post-fix run but failed repeatedly in the expanded run.
- Bing returned results unrelated to these queries; its existing validation
  correctly marked them degraded. Google and Mojeek served recognized challenges.
- Marginalia exceeded the provider timeout on multiple queries.
- Crossref returned one HTTP 429 and later recovered.
- Repeated failures opened the Bing, Google, Mojeek, and Yahoo breakers. The status
  tool exposed their errors and cooldowns while working providers remained usable.
- One DOI link led to a document larger than 10 MiB. The reader now rejected it
  explicitly instead of pretending that a truncated download was complete.

## Validation

- Baseline `go test ./...` passed.
- Post-change race and atomic-coverage suite passed, including CLI, stdio, and
  streamable HTTP integration tests.
- `go vet ./...` passed.
- Lint passed for all tracked packages. The original untracked arXiv provider was
  excluded from that lint invocation because it has unrelated formatting and
  unused-constant findings; its source was preserved.
- Pagination fuzzing completed 58,070 executions and page-range fuzzing completed
  120,158 executions over ten seconds each, with no failure.
- Live post-fix assertions verified query pagination, large window handling,
  actual arXiv PDF content, and explicit no-match output. The final runner
  completed 29 tool calls: all positive calls succeeded and all three invalid
  requests were rejected. The real paper also passed a column-order assertion.

The optional live runner records full protocol responses and timings outside the
repository. It reports tool errors as observations; a completed runner is not an
assertion that every external site worked.

```sh
go build -o /tmp/search-mcp .
python3 scripts/audit_mcp.py --binary /tmp/search-mcp --output /tmp/mcp-audit
python3 scripts/audit_mcp.py --binary /tmp/search-mcp --output /tmp/mcp-audit-expanded -- \
  --providers duckduckgo,yahoo,bing,google,marginalia,mojeek,wikipedia,hackernews,stackexchange,crossref \
  --retry-max-attempts 1
```

## Remaining limits

Free general search still depends on unstable upstream HTML and datacenter-IP
blocking; successful fallback cannot make blocked providers reliable. Reader
challenge detection recognizes specific interstitials and does not cover every
access wall. JavaScript-only pages still need a browser-backed reader.

PDF extraction has no OCR and its two-column detection is heuristic. Complex
layouts, mixed-direction text, font encodings, and deeply malformed PDFs remain
limitations of the underlying library. Panic recovery is not a substitute for
process isolation or CPU/decompression budgets. Downloads over 10 MiB and PDFs
over 10,000 pages are unsupported.

Caches have bounded rendered content but retain entry-count-based eviction;
concurrent identical requests are not coalesced. Specialist providers can dilute
general-query rankings when explicitly added to fan-out, so the general-provider
default was retained. Keyed providers were covered by hermetic tests where
available; live quota-bearing integrations were not configured for this audit.
